# 文件管理规范

版本 management-1.0，2026-10-12。目标是让源码、配置、原始资料、正式数据集、实验和发布资产有明确位置、状态和来源。当前仅建立制度，不大规模搬迁旧数据。

## 1. 目录职责

| 位置 | 职责 | 管理方式 |
| --- | --- | --- |
| README.md | 项目入口、当前阶段、主文档索引 | 不重复维护研究细节 |
| AGENTS.md | 自动化协作者的阶段与发布约束 | 与用户最新指示和 STATE 一致 |
| docs/research/PLAN.md | 唯一主计划 | 有版本、日期和变更依据 |
| docs/governance/ | 制度、阶段状态、资产登记 | 文本纳入本地 Git |
| docs/usage/、docs/data/ | 已实现功能、字段与来源说明 | 旧试验文档标记历史状态 |
| docs/releases/ | 已发布版本的历史记录 | 不用旧发布说明证明当前正式能力 |
| src/cs_youoweme/ | 可复用实现 | 采集、变换、特征、模型等在包内按职责扩展 |
| scripts/ | 薄命令入口与维护检查 | 不堆积爬虫实现或实验结果 |
| sql/ | 可复用、口径明确的查询 | 与 schema 版本对应 |
| config/ | 无密钥配置、空白模板、本地私有配置 | 配置记录版本，真实值只在忽略文件 |
| tests/ | 合成资料、离线测试、必要集成验证 | 不把真实凭证或完整市场资料放入测试 |
| data/local/ | 原始资料、候选数据、正式集、实验、报告与旧资产 | 全部私有、Git 忽略 |
| data/samples/ | 已有公开样本 | 本轮冻结；只有 P06 审查后才调整 |

保留现有源码目录，不为未来功能预先创建大量空目录。未来特征、标签、模型和回测模块优先放在 Python 包内。数据目录只保存数据与产物，不放爬虫源码。

## 2. 私有数据的生命周期目录

新任务在对应 part 获得范围后采用以下约定；本轮不创建或填充这些运行目录：

```text
data/local/
├── raw/<source>/<run_id>/                 原始观察，追加保存
├── staging/<source>/<run_id>/             标准化但尚未验收
├── datasets/<dataset_id>/                 冻结且明确用途的数据集
│   ├── manifest.json                     来源、版本、窗口、规则、校验
│   ├── tables/                           面板或事件表
│   └── reports/                          质量与准入说明
├── artifacts/<experiment_id>/            特征、模型与运行产物
├── reports/<experiment_id>/              评估、图表、预测与配置摘要
├── universes/<universe_id>/               正式研究名单版本
├── manifests/                            运行与资产登记
├── archive/                              已登记的历史资料
└── progress/                             本地工作交接和状态记录
```

旧 `database/`、`universes/*.json`、`recon/` 等位置不立即迁移，在资产登记中记录原路径和历史试验状态。P03 新试跑使用独立运行位置，不追加到旧试采库；具体数据库路径由该部分确定。

原始资料不原地“清洗覆盖”。派生表必须能追溯输入和变换；冻结数据集、名单和实验不能由下一次运行无声覆盖。当前“latest”指针只能指向版本，不替代版本文件。

## 3. 命名与版本

- 文档按职责使用固定名称，如 PLAN、STATE；不使用 final、最终版2、最新版之类名称。
- 运行 ID 使用 `p03_uu_YYYYMMDDTHHMMSS+0800_<短标识>`；时间以北京时间展示，记录中另保留时区明确的 UTC 时间。
- 数据集 ID 使用 `uu_<用途>_<窗口>_<版本>`，实验 ID 使用 `exp_<日期>_<短标识>`。
- 计划版本、schema 版本、数据集版本、模型版本、代码版本分别记录，不用一个版本号代替所有状态。
- 修改已冻结输入、过滤、标签或特征定义后产生新版本，不能继续复用旧 ID。
- ID、模板、精确磨损与金额的类型在字段契约中明确；不让 Excel 等工具自动改变商品编号或精度。

## 4. 资产状态与准入

| 状态 | 意义 | 是否可训练 |
| --- | --- | --- |
| legacy / unreviewed | 历史试验或未经新口径检查 | 否 |
| candidate | 对应部分产生的候选资产 | 否 |
| validated | 对某个明确用途通过验收 | 仅在记录的用途内 |
| frozen | validated 输入与规则已固定 | 可按对应协议使用 |
| rejected | 不满足用途，保留拒绝原因 | 否 |
| archived | 暂不使用但保留追溯价值 | 否 |
| release-approved | 经最终发布审查 | 公开资格，不自动代表训练资格 |

文件路径存在、解析成功、测试通过或过去已公开，都不等于 validated。准入要记录来源身份、时间语义、字段口径、质量指标、预期用途、限制、审查日期与依据。真正无用且无追溯价值的资料才进入删除清单。

## 5. 清单的必需内容

每个运行至少记录 source、venue、run_id、phase、开始／结束时间、计划窗口、采样预算、schema、代码提交、配置摘要、请求／失败／重试计数及原始校验值。

每个数据集另记录 dataset_id、parent_run_ids、资产状态、允许用途、来源时间可得性、规格范围、单位、缺失和去重规则、行数／覆盖、质量报告、变换版本及输入输出 SHA-256。

每个实验另记录 experiment_id、dataset_id、名单版本、特征／标签／成本版本、训练和测试窗口、随机种子、参数、基准、全部尝试与结果。不只保存表现最好的一次。

未知字段标记 unknown 或 unavailable，不填造假的完整率或虚构来源时间。清单和日志不保存密钥、Cookie、认证头或与研究无关的个人资料。

## 6. Git 与公开发布

- 每个 part 在本地功能分支记录；当前分支为 `planning/uu-research-reset`。
- 文档与代码的可审查修改可以本地提交。当前不 push，不创建 GitHub PR，不合并远程或发 release。
- 真实 `config/.env`、数据库、原始响应、完整名单、模型产物和运行报告留在忽略目录。公开 `config/.env.example` 必须为空。
- 已有远程仓库保持原状；最终 P06 以明确的发布允许清单重新筛选可复用内容。
- P06 发布前检查工作区、暂存区、可达历史、示例、说明和产物，确认凭证与个人信息隔离。
- Git 只记录文本、小型源码和经审查示例；不依赖 Git 保存全量市场资料。

不因文件“已经被忽略”就把真实密钥放进模板或输出。检查工具只显示位置和结果，不显示值。涉及项目配置时不读取或展示凭证内容来证明它存在。

## 7. 移动、删除与备份

不在未知状态下递归清空 data、数据库或原始响应。删除／迁移前列出精确目标、用途、登记状态和保留依据，验证绝对路径位于指定项目范围；用户已授权的明确清理可以执行，不重复确认。

迁移后核对路径引用、清单、校验、schema 与恢复能力。SQLite 使用备份接口或在停止写入并完成 WAL 处理后操作，不在写入时单独复制主文件。备份恢复过程必须能够验证，不能只保留一个看似完整的文件。

密钥、个人资料和独有来源证据不当作一般冗余删除。备份也属于私有资产。旧正式标签与历史日志不是当前研究的准入证明。

## 8. 每部分的收尾

交付当前部分的文件，更新 STATE、必要的资产登记和本地进度，运行与修改相适应的检查，报告完成项、证据和未解决项，然后停止。

纯文档变更检查链接、状态和表述一致性及凭证隔离；不为此启动采集、训练或全套模型实验。进入下一 part 由用户下一次指示确定，不自动续跑。
