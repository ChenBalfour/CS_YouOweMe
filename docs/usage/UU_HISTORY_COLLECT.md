## 用户操作

1. 在 Edge 正常登录 UU，打开需要采集的商品规格页。先确认名称、磨损与普通/特殊版本；不同模板分批采集。
2. F12 → Sources（源代码）→ Snippets（代码段）→ New snippet。把 collect_uu_charts.js 全文复制进去，保存后运行。页面右上方出现采集面板。脚本只用于已登录的 `https://www.youpin898.com`，不需要复制请求头、Token 或 Cookie。
3. 在原商品图表中选择 **成交价格 → 半年**，让页面正常请求成功。工具支持 fetch 与 XMLHttpRequest；仅观察指定 price/trend/data 端点。若本来就在半年，先切换到另一个范围，再切回半年。
4. 面板显示捕获到的模板编号与实际 day。确认原网页确实选中半年，填写商品完整名称、磨损与版本，点击“确认当前窗口为半年，开始本轮采集”。半年参数来自这次正常请求，不写死180。价格与数量分别采用各自实际可选的时间范围；不再请求15天价格、90天数量或半年数量。
5. 面板采集剩余组：每次间隔5秒、并发1、最多7组尝试（含正常页面已成功的半年一组），每请求最多30秒、总轮次最多180秒、每响应最多2MiB。没有自动重试。请保持页面前台，不切换账号或商品。
6. 完成、失败或手动停止时下载 `uu_charts_*.json`。若浏览器阻止自动下载，点击“下载已保存结果”；关闭/刷新页面前先保存。登录头只在本页请求的内存中使用，不写入下载文件、控制台或本地项目。
7. 打开新 Notebook，选择下载文件并执行离线入库单元格；也可用下面的 CLI。输出目录必须全新，不能覆盖旧批次。

```powershell
python -B scripts/import_uu_chart_batch.py "C:\path\to\uu_charts_your_download.json" --output data/local/staging/uu_charts/browser_batch_01
```

Notebook 可打开文件选择框，避免手工填写下载路径。离线导入不启动采集、不读取登录配置。

## 停止、保存与恢复

- HTTP 401/403/429、登录/应用错误、空数组、结构或数值异常、超限和网络失败会停止整轮，保留失败、待采及成功状态。HTTP失败不保存可能带账户信息的错误响应正文。
- 访问停止状态只保存原因与时间到浏览器 localStorage。再次运行不会自动解除；先由用户正常访问成功，再点击人工恢复确认。旧 Python 入口的429停止记录不改写，不通过新ID、换IP或伪造凭证绕过。
- 用户中断后可在面板载入之前的下载批次，重新以同模板的正常半年响应确认。成功任务不重复采；仅继续从未尝试的 pending。失败/结果未知的任务不自动重试，因此恢复可能仍是部分完成，报告如实列缺口。
- 浏览器内数据暂存在内存；刷新、关页、系统崩溃可能丢失尚未下载的进展。可随时手动下载检查点。当前版本不承诺无人值守24小时、自动续登录或崩溃后零丢失。
- 页面请求头可能有有效期、一次性签名或附加校验，能捕获正常请求不保证后续七组成功；错误时停下，按返回状态核验，不能反复循环。

## 落盘与时间口径

每次导入在私有 `data/local/staging/uu_charts/<批次>/` 保存 batch_input.json、chart_batch.sqlite、points.csv、report.json、manifest.json 和三个对应脚本。数据库 tasks 表记录7组任务状态，points 表按 task_id/sequence 保留点；金额为精确文本，数量为整数，null不填零。

各窗口独立保存；7天与半年同一时间点也不相互覆盖，冲突留给后续重叠/修订核验。不预设采样频率，按原时间戳统计实际点数和间隔。响应正文是浏览器解码文本或 XHR JSON 再序列化结果，不冒充原始传输字节。browser_received_at 只说明当前拿到这份历史的时间，historical_available_at 仍为未知，不能据此声称这些历史值过去已可见。

用户的44828新版真实批次已完成七组，共1335条窗口记录、947个不同指标/时间点；半年请求day=180已实证，7天数量每小时一次，15/30天数量每4小时，价格间隔不固定。完整商品身份仍未独立核验，多轮稳定性仍待验收；早先的639点属于旧版失败批次的三组成功记录。技术样例不能自动加入首批百元名单。已有价格/数量样例与字段映射见[图表说明](../data/UU_HISTORY_CHART.md)。

## 历史曲线与当前报价为什么都要保存

**当前报价既用于决策，也能积累为未来训练数据。** 目前取得的历史接口返回成交价格曲线与在售数量，未证明会保留过去最优求购价、最优在售价、价差、各价位有效数量与属性限制。成交曲线或OHLC压缩结果无法完整还原这些报价状态，不能假定明天下载K线就能找回今天的盘口。

| 数据 | 训练/研究用途 | 当下决策用途 |
| --- | --- | --- |
| 历史成交价格曲线 | 构造价格序列、波动与未来参考价格标签；统计定义待确认 | 提供市场背景，不等于当前能买或能卖的报价 |
| 历史在售数量 | 供给水平、变化和价格/供给组合的候选特征 | 判断供给变化；下降不等于卖出，不能代替成交量 |
| 当时在售/求购价及数量快照 | 留存后可研究价差、报价变化、流动性与成本；需处理来源时效及匹配 | 估计当前购买成本、有效价差，核对解锁后的潜在退出条件 |
| 单件属性、求购限制与更新时间 | 判断样本可比性、执行标签和回测可实现性 | 防止拿受限高价求购与普通件直接比较 |

现有前向 Notebook 采的是 SteamDT UU 来源**汇总报价**，尚未取得完整匹配盘口；不能把汇总求购数量当作最高价位的可成交深度。

初版采用两层：价格模型先用已有同口径历史特征预测约一周后的来源价格及不确定性；决策层再结合决策时已取得的匹配买价、价差、成本与退出证据。当前报价积累到足够、覆盖一致的样本后，再通过时间验证决定是否加入模型。训练没有的字段不能在推断时临时添加；今天的盘口不能回填成过去每天的真实盘口。

供给信息可能增加价格以外的信号，但不保证能领先趋势。长期目标仍是七日CD实际解锁后尽快退出；盘口、属性和成本未验收前保持L0，不将价格预测包装成可执行收益。

## 真实稳定性验收

已核验44828一轮七组状态、真实点数/覆盖、下载和导入。该文件是新建批次，不能据此宣称真实中断恢复通过；下一项核对规格/价格统计并检查多次采集一致性、访问停止及恢复。按多次正常使用结果再确定更新频率：首次获取完整窗口，之后近期窗口增量与长期低频复核分开，不必每小时重复下载全部半年。具体调度仍待接口时效、限制和预算证据，当前没有后台循环。

## 登录与 SteamDT 数据结合

UU 需用户在自己的浏览器正常登录。本工具只在同一页面内存中复用刚刚正常成功的图表请求，不导出认证头或Cookie。会话过期、额外验证和风控需要用户处理，不能承诺自动续登录或无人值守稳定运行；不向聊天索取密码、验证码或Token。

**UU 直接图表为主要来源，SteamDT 为辅助，原始数据分别保留。** 下面是结合方案，尚未实现正式合并数据集：

1. 先建立 UU templateId 与 SteamDT itemId 的精确映射，核对同涂装、磨损、普通/特殊版本和属性范围。44828目前只有用户请求编号证据，不能猜商品名称。
2. 各来源保留指标定义、窗口、原始点时间、来源更新时间和实际取得时间。后续只把决策时已经可得的数据按时间关联；不用未来较近的一点替代过去时点，过期值保留时效标记。
3. UU成交曲线、SteamDT UU来源K线、两边汇总在售/求购报价是不同指标，分别成列；不直接拼接成连续价格，也不取平均当作真值。差异先核查统计方法、时间与属性范围。
4. 历史在售数量以已核验的UU直接曲线为依据；SteamDT可提供明确UU来源的小时走势及汇总报价辅助观察，但未知量额与混合逐笔不升级为真实UU成交。报价缺口不能无声以另一来源补齐；将来若采用回退，须明确来源切换与质量。
5. SteamDT转述UU的价格不是独立市场的第二份成交样本。相同信息不重复计样本，也不当成两份独立证据。是否增加有效信息需等数据核验后再研究。

当前工作只包括采集器、落盘与数据质量核验；正式数据集与模型均为0，没有开始训练。
