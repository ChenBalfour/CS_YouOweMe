## 当前结论

已完成“七品小时采集库 → 七品清洗研究版”，另有“次时代旧严格样本 → 固定基准 → Notebook图表”。**两条链路尚未接通：新清洗库还没有生成七品预测特征与标签。** 下一项开发应先接通这一步，再比较新模型。

目前是 **L0 来源研究**：七品清洗版1版、单品候选2版（样本表一致）、固定规则评估1版、拟合模型0、完整买卖决策未实现。研究数据已可复核，不代表正式训练或UU执行准入通过。首批七品足够验证工程和初步方法；泛化与盈利能力仍需新数据检验。

目标保持：SteamDT显式UU小时数据为主要研究输入，UU补供给与当前匹配报价；每日判断买入是否值得，实际七日CD解锁后尽快退出。来源参考价不等于可成交价。需要每日新鲜信息，每周做较深复核，不能仅每周更新一次却称每日实时决策。

## 当前卡点

| 优先级 | 卡点 | 对结果的影响 |
| --- | --- | --- |
| 1 | 清洗层尚未接入新七品特征/标签和评估 | 目前看见的预测仍是原库严格单品基准；不能拿质量通过数当成熟训练样本数 |
| 2 | 简单趋势未超过持平；旧测试已经查看 | 不靠换复杂模型保证提升；下一轮需新规范、滚动验证和未看过的前向留出 |
| 3 | 历史available_at、量额推算/缺失口径未完全确认 | 回顾结果可能包含后来修订；来源量额先作辅助，不声称严格PIT回测 |
| 4 | UU当前可匹配ask/bid、数量、费用和收货/解锁/出售/结算尚未接通 | 不能从上涨预测直接生成可执行净利润或买入建议 |
| 5 | 仅一次真实跨日和UU单品单轮成功 | 需要继续积累每日有限运行记录、凭证失效与失败停止证据，才能判断长期可靠性 |

| 顺序 | 要做什么与交付物 | 验收依据 |
| --- | --- | --- |
| 1：接通清洗→研究 | 冻结七品新特征/标签规范，显式选择clean dataset ID；价格多尺度收益、波动、尾部风险、缺失率/最长缺口/信息年龄和同日期跨品信息。分别建立七日终点价格与路径风险标签 | 从manifest可复算；扰动未来不改变输入；NULL不混0；终点真实且成熟才有点标签，路径缺失单独标记；跨品同日期划分＋7日标签隔离；原库与旧版不改 |
| 2：建立新评估 | 严格输入与容缺输入并列；持平为底线，先小模型，再按调研选择预训练时序/表格模型对照。预处理/拟合只用训练，选择只用验证 | 滚动时间验证、极端行情分层、七日重叠说明；报告误差及预测区间覆盖。旧test只作探索，新前向数据作真正留出；没有提升也完整记录 |
| 3：并行积累执行证据 | 用户显式每日有限daily更新、每周weekly复核；保存新鲜度。接UU同规格、同条件、同采集时刻的在售/求购/数量与当前费用、实际解锁状态 | 不借今天盘口回填过去；报价未知则不算利润。检查访问停止、失败、来源修订和可得时间；其他六品的执行属性另验收 |
| 4：交付L1决策demo | Notebook并列显示历史/预测区间、来源参考价、可实现退出情景与成本；输出候选/观察/暂不购买/数据不足，并保存逐日决策账本 | 每条判断可追到数据/特征/模型/成本版本；记录CD内不能卖、解锁后等待/未成交/结算；先前向模拟验证，不保证每日有进出 |
| 5：扩大与发布 | 有新留出证据后再考虑更多价格带/品、部署与正式版本；保留失败实验和原始证据 | 扩品有明确增益与数据预算；发布范围单独审查。当前GitHub代码迭代不代表正式模型或交易发布 |
