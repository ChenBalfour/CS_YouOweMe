# SteamDT研究主序列与UU补充数据对齐方案

版本 **source-alignment-plan-1.0**，2026-10-15，北京时间。状态：**研究方案，未创建正式特征表或训练模型**。本页补充[产品](../PRODUCT.md)、[架构](../ARCHITECTURE.md)和[进展](../PROGRESS.md)，不改写既有数据与冻结采集源码。

## 来源分工

建议优先将SteamDT显式YOUPIN小时OHLC作为研究主序列候选，保留其可空来源量额；UU直接图表补充历史在售数量与价格对照，UU当前可匹配报价和规则决定执行可行性。七日CD实际解锁后尽快退出的策略保持，数据供应方与交易执行平台分别记录。

| 数据 | 拟用角色 | 当前边界 |
| --- | --- | --- |
| SteamDT显式UU小时OHLC | 连续价格、收益、波动和跨周期研究的主要原始输入候选 | 既有试跑每批720小时，不能据截图宣称完整半年或2025-06-01以来小时历史；先核验覆盖、缺失、平台与时间定义 |
| SteamDT来源volume/turnover | 来源量额特征候选 | 旧响应确有字段，但存在null，真实计数/推算程度/统计范围未确认；不写成已核验UU实际订单或结算额 |
| UU直接历史图表 | 在售供给特征、与来源价格对照、检查修订和时效 | 单品七组1360条窗口记录通过，962个不同指标/时间点；数量最多已见30天，价格与数量/各窗口末点不统一 |
| UU可匹配当前买卖报价 | 买入前成本、属性匹配及解锁后退出评估 | 汇总最高求购不是任意物品可卖价；仍需属性、有效数量、手续费和规则证据 |

用户截图显示1小时/4小时/日K/周K及量额，也显示“今日推算成交”和某小时成交额n/a。它支持网页能力线索，不能单凭截图确认每个字段均为UU真实完整成交。其上方商品为USP消音版/小绿怪/崭新；该截图没有给出UU templateId与SteamDT itemId配对，不能因此把44828自动映射为该商品。

SteamDT[开放API饰品K线文档](https://doc.steamdt.com/428124801e0)明确标注“不包含成交数据”。本项目此前读取的网页 `/user/steam/category/v1/kline` 与开放API `/open/cs2/item/v1/kline` 不同，不能用其中一套的说明推断另一套已具备或缺少全部字段。旧逐笔“三方推算”仍不能套用为UU真实订单；小时量额按[既有契约](UU_FIELD_CONTRACT.md)保留未知统计口径。

## 第一版频率方案

原始层按来源真实频率保留：小时K线、UU不规则价格点、1小时或混合2/4小时数量点不插值覆盖。研究样本建议从**每日固定决策时刻**开始：计算此前已闭合且可得的小时信息、过去24小时/数日的趋势与波动、最近已知在售数量及其年龄；小时原始数据仍保留。4小时/小时样本作为后续对照，样本窗口、时刻和陈旧上限待覆盖检查后冻结。

较粗的观察无需人为加噪声、制造波动或拆成伪小时成交。把一个库存值沿用几小时，只表示尚无新观测，不增加独立信息量。线性/样条插值若用到了未来端点，会泄露未来；本阶段不把插值曲线作为真实特征或标签。

| 字段类型 | 合并到4小时/日等较粗窗口的规则 |
| --- | --- |
| 已闭合OHLC | 开盘取首开、最高取max(high)、最低取min(low)、收盘取末收；要求相同来源/规格/定义，检查子桶覆盖 |
| 来源成交量/额等区间流量 | 仅对不重叠且口径一致的子桶求和；缺失不补0，部分覆盖另标，所有子桶为空不能算0 |
| 在售数量等状态快照 | 取截至决策时点最后已知的有效状态，附时间/年龄/是否新观测/缺失标记；不能把一天数次库存相加当日库存或成交量 |
| UU不规则价格点 | 独立保存最近观测、年龄与观察点统计；抽样点极值不冒充该时段全部真实成交的OHLC |

以小时K线聚合出4小时/日/周特征，与平台原生同周期结果需要核对桶边界、时区、缺失和计算口径；不同时把小时与相应日/周量额相加，避免重复。当前尚未验证原生4小时/日/周接口类型及完整覆盖，不猜参数开始采集。重采样需显式规定时区、桶开闭和标签，见[pandas重采样文档](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.resample.html)。本次未引入pandas运行依赖。

## 时间对齐与信息可得边界

各来源先映射精确商品、普通/特殊版本和磨损，再按决策时间匹配，不按数组序号或最近绝对距离拼接。原始时间保存，统一时区后仍分别记录source_event_time、bar_start/bar_end、source_update_time、collected_at和available_at（未知则为空）。

对决策时点t，只允许使用已在t之前可得的数据。快照从过去找最后一条，禁止向前找未来点或用未来点回填；设置陈旧上限，超限则缺失。每个慢字段附last_observed_at、age、is_new_observation、missing；不让重复沿用伪装为新采样。实现可参考[pandas.merge_asof的backward与tolerance](https://pandas.pydata.org/docs/reference/api/pandas.merge_asof.html)，但该函数只解决时间匹配，本身不能证明历史可得时间。

示意：11:00数量1000，15:00数量1200。若11点数据在13点前已经可见，则13:00只能沿用1000并标记年龄2小时；不能用15点结果插成1100。UU本轮图表time是点时间，当前下载时间不是其历史发布时间；先检查可得时间证据，不能因为time早于t就认定回测无泄漏。

未收盘小时不能当完整小时高低收/量额；未结束日线和周线也不能用最终值做盘中输入。若历史发布/修订时刻缺证，标签为historical_availability_unknown；延迟情景只能明确作为假设做敏感性检查，不能声称还原了真实当时信息。

## 不同历史长度与验证

SteamDT较长价格历史（以实际覆盖为准）与UU已见30天在售历史分别保存。先规划主序列基准A，再在双方重叠的同商品/同日期比较加数量的B；比较要控制评估区间，不能将不同时段成绩直接归因为库存特征。库存缺少的旧日期保持缺失，不从今天回填，也不因它只有30天就直接丢弃全部较长价格历史。

第一轮按时间前推并考虑七日目标重叠，不做随机打散；这仍是未来P04/P05方案，不是已开始训练。价格预测是来源目标，成本和实际可卖报价另验，不把来源量额直接当可退出规模。

## 登录配置与更换商品

- 登录配置通常属于账号/设备会话，运行时本地读取，不以换商品或换窗口为由重新生成。一次resume中的六个真实成功请求复用了同一次配置读取，说明本次无需逐请求填写。
- Authorization/Cookie可能过期、退出登录失效或触发额外校验；deviceid/其他字段保持正常会话原值，不为每个商品随机更换。有效期与必需字段未证实，遇到401/403/业务错误先停，再正常登录更新本地配置；不自动刷新或轮换账号。
- 新商品一般只改独立商品清单中的template_id、item_label和已确认的half_year_day；SteamDT使用自己的itemId，二者不能互换。新清单另建probe运行，不把新商品塞进已经完成的44828运行；先做单请求。沿用登录配置是否对该新商品有效仍以有限结果为准。
