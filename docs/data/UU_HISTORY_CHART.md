# UU 网页历史图表与决策时间口径

版本 uu-history-chart-1.0，2026-10-14，北京时间。依据是用户提供的两张 UU 商品页截图、一张 BUFF 商品页截图和补充观察；原图、SHA-256 与接收日期私有保存。UU 截图拍摄时间、商品完整名称和 templateId 未提供。本轮只记录证据和离线接口线索，没有取得登录后的历史图表响应。

## 已见界面与待核验颗粒度

截图明确显示“UU价格走势”，指标可选“在售数量”或“成交价格”。在售数量图的可见提示为 2026-10-10 19:00:00、1328；成交价格图的可见提示为 2026-10-03 19:18:50、36 元。商品参考价格为 44.4 元，仅作技术例子，不加入首批百元候选。

| 页面范围 | 用户观察的频率 | 后续核验 |
| --- | --- | --- |
| 近 7 天 | 每小时 1 个点 | 检查原始时间戳、相邻间隔、缺采和边界 |
| 近 30 天 | 每天 4 个点 | 核对各日点数，不预设严格每 6 小时一次 |
| 近 90 天 | 每天 2 个点 | 核对各日点数，不预设严格每 12 小时一次 |
| 半年 | 每天 2 个点 | 核对实际起止日与点数，不能直接按 180 天写死 |

频率是用户界面观察，尚未以接口响应验证；曲线平滑线段不是额外采样点。两个指标是否采用同一时间网格、短长窗口是否重新聚合、是否存在回填或修订，均待核验。

## 字段分别解释

- 历史在售数量：该时点的来源库存/挂牌数量观察，具体范围待核验。数量变化同时受新增、撤单、重新上架和成交影响，不能当成交数量。
- 历史成交价格：来源曲线所标价格，仍需确认代表最新一笔、均价、中位数或其他统计，以及是否混合细磨损等属性；不先认定为某件可实现卖价。
- 历史成交额：一段时间内成交价格与成交件数的金额汇总，是不同字段。不能把成交价格乘在售数量当作成交额。
- 完整单件盘口与逐笔订单：图表本身没有提供单件属性、求购条件、各价位深度或订单/结算记录；历史曲线存在不代表这些字段已取得。

结论修正为：**UU 界面展示了历史在售数量和成交价格，优先验证其结构化读取与统计口径。** 当前“尚未取得/验收”不能写成“UU 没有这类历史”。也不将这些图表与 SteamDT 来源量额、混合推算逐笔或官方开放 API 无声合并。

## 数据保存与后续有限核验

### 登录前提与辅助来源

用户明确 UU 价格走势需登录本人账号后查看。BUFF 截图为 UMP-45 黑色魅影久经，展示“成交记录”“价格走势”入口，走势区域明确提示先登录 BUFF，未显示历史曲线值。这证明入口和登录前提存在，不能据此宣称完整历史、字段或匿名访问已通过验收。截图中的久经价格低于百元范围，仅作功能例子，不加入候选。

BUFF 只作辅助来源；其成交记录、行情和平台费用不能替代 UU 的执行价格、成交数量或退出证据。两平台需要相同商品、版本、磨损和币种的映射及各自时间、统计范围，分别保存，不合并为 UU 成交。

用户已确认使用 Edge；浏览器工具连接多次失败，重置后仍报 nodeRepl.fetch request failed，尝试创建内置浏览器页面也超时，未取得用户登录会话。后续在可访问浏览器中由用户完成必要登录，再读取正常可见页面。凭证、验证码和会话 Cookie 不写入文档、Notebook 或 Git，不从截图或历史文件推断登录资料。

### 已有脚本的离线接口线索

2026-10-13 保存的 UU GoodsList 脚本（证据请求 9，原始哈希核对通过）存在以下 POST 相对路径定义。它们只证明前端具备相关调用，不证明接口当前可用或权限成立，本轮没有请求这些端点。

| 相对路径 | 静态线索 |
| --- | --- |
| api/youpin/price/trend/filter/info | 使用 templateId 读取图表筛选信息 |
| api/youpin/price/trend/data | 单类历史图表请求定义 |
| api/youpin/price/trend/dataList | 多类历史图表请求定义 |
| api/youpin/price/trend/getValidDateTime | 有效日期范围请求定义，读取 validStartDate/validEndDate |

调用构造涉及 templateId、day、templateTypeName、filterTemplateTypeNames、orderType、startDate、endDate、customizeDay。脚本枚举字面包含 1=成交价格、11=在售数量、14=在售价格、10=售出最低价格；响应图表读取 tradeDataList/tradePriceList/blockNum，点读取 time/price。枚举和字段名不足以解释统计口径，不猜测 day 值或数值单位，也不把相对路径擅自拼到已受限主机执行。

分别保存商品身份、来源、指标、页面窗口、原始时间戳与值、采集/返回时间、实际采样间隔、请求 ID 和原始响应哈希；未知统计方法与属性范围保持 unknown。长短窗口分开存原始批次，重叠点比较后才去重；同一时刻不同值保留修订来源，不无声选择有利版本。

后续先核验一个已确认身份的百元规格，再判断是否扩大。需确认 7 天/30 天/90 天/半年四个窗口的响应字段、实际点数和重叠差异；同时记录该网页登录/访问前提与请求预算。旧 UU 主机 429 状态保持停止；存在页面功能不代表当前采集入口已通过验收。

## 对 demo 的影响

用户策略明确为 **七日 CD 解锁后尽快退出**，覆盖旧计划中的 14/21 日候选。预测参考窗口可先用同一决策时点约 +168 小时的来源价格；执行则以实际收货、交易保护和最早可卖状态确定退出时点，等待成交与结算单独记录。

建议初版每小时记录前向观察、每日固定时刻推断、准备买入前刷新可匹配报价。当天决策可用已完成的昨日序列和当前已取得的快照；不能使用当天结束才知道的收盘、高低价或之后补齐的历史值。该方案目前是设计，不启动新观察、训练或下单。

初版长期模型可先按统一日粒度构造序列，近期小时信息另外保存；具体取样时点、输入窗口与聚合方法在 P04 冻结。不能把半年每天两点插值成真实小时历史，或把现在才拿到的历史记录假定成过去决策时已发布。不同频率分别记录覆盖和缺失，训练与推断保持相同可得时间定义。

历史成交价格有望改善价格预测目标，但解锁后可供货的求购价格、匹配数量与成本仍需前向证据。当前仅 L0 来源观察，正式数据集、模型和执行准入尚未完成。关联：[主计划](../research/PLAN.md)、[字段契约](UU_FIELD_CONTRACT.md)、[当前状态](../governance/STATE.md)。
