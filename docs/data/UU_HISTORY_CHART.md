## 请求上下文与响应字段

用户提供的 POST 端点为 `https://pc-api.youpin898.com/api/youpin/price/trend/data`。安全请求正文包含 `templateId="980"`、`orderType`、`day`、`filterTemplateTypeNames=[]`、`templateTypeName=""`、`customizeDay=false`。价格请求为 orderType=1/day=30；数量请求为 orderType=11/day=7 或 15。day 和编号的数字字符串可规范为整数，但必须保留原请求正文。响应自身没有 templateId/orderType；本次关联依据用户页面选择与提供的请求，不是程序捕获到的请求响应配对。980 的完整商品身份、磨损与版本尚未独立核验，只作技术样例。

| 字段 / 上下文 | 解释与保存方式 |
| --- | --- |
| code=0 | 来源表示请求成功；不代表数据用途验收 |
| timestamp | 响应中的毫秒时间戳；价格 1791952651766、数量 1791953107780，分别为北京时间 12:37:31.766、12:45:07.780 |
| data.tradeDataList | 真实图表点数组；不把辅助数组当额外观察 |
| point.time | 13 位 Unix 毫秒时间戳；保留毫秒及 +08:00 展示，拒绝当秒解析 |
| point.price + orderType=1 | 成交价格曲线值，独立列 source_trade_price_cny；精确 Decimal / SQLite 文本，样例 28.40–43.92 元 |
| point.price + orderType=11 | 在售数量曲线值，独立列 source_listing_count；"1112.00" 转整数 1112，样例 1078–1893；非整数数量拒绝，不截断 |
| localDate | 来源日期，存在时核对北京时间日期；数量投影未保存该字段 |
| sourceType | 保留原值，原两份响应均为 0；该命名空间含义未知，不继承 SteamDT 逐笔代码的场所分类 |
| proportion、tradePriceList、blockNum | 保留作图表辅助字段，业务定义待确认；不当收益率、成交量或采样次数。数量投影省略逐点 proportion/sourceType/localDate |

输入 null 与零分开；相同时间的不同值保留并标记冲突；逆序、未来时间和日期不一致标质量问题。指标由显式请求上下文决定，不能仅凭字段名 price 或数值大小猜测。两份数据采用不同时间网格，不按行号拼接，不将数量乘成交价格充作成交额。

## 字段分别解释

- 历史在售数量：该时点的来源库存/挂牌数量观察，具体范围待核验。数量变化同时受新增、撤单、重新上架和成交影响，不能当成交数量。
- 历史成交价格：来源曲线所标价格，仍需确认代表最新一笔、均价、中位数或其他统计，以及是否混合细磨损等属性；不先认定为某件可实现卖价。
- 历史成交额：一段时间内成交价格与成交件数的金额汇总，是不同字段。不能把成交价格乘在售数量当作成交额。
- 完整单件盘口与逐笔订单：图表本身没有提供单件属性、求购条件、各价位深度或订单/结算记录；历史曲线存在不代表这些字段已取得。

结论修正为：**UU 界面展示了历史在售数量和成交价格，优先验证其结构化读取与统计口径。** 当前“尚未取得/验收”不能写成“UU 没有这类历史”。也不将这些图表与 SteamDT 来源量额、混合推算逐笔或官方开放 API 无声合并。

## 数据保存与后续有限核验

### 登录前提与辅助来源

用户明确 UU 价格走势需登录本人账号后查看。BUFF 截图为 UMP-45 黑色魅影久经，展示“成交记录”“价格走势”入口，走势区域明确提示先登录 BUFF，未显示历史曲线值。这证明入口和登录前提存在，不能据此宣称完整历史、字段或匿名访问已通过验收。截图中的久经价格低于百元范围，仅作功能例子，不加入候选。

BUFF 只作辅助来源；其成交记录、行情和平台费用不能替代 UU 的执行价格、成交数量或退出证据。两平台需要相同商品、版本、磨损和币种的映射及各自时间、统计范围，分别保存，不合并为 UU 成交。

用户已确认使用 Edge；浏览器工具连接多次失败，内置浏览器创建超时，agent 未取得登录会话。用户手动导出响应已经支持本次离线核验，因此字段检查不必等待浏览器连接修复。凭证、验证码和 Cookie 不写入文档、Notebook 或 Git；只复制响应正文，用法见 [导出说明](../usage/UU_CHART_EXPORT.md)。

## 对 demo 的影响

用户策略明确为 **七日 CD 解锁后尽快退出**，覆盖旧计划中的 14/21 日候选。预测参考窗口可先用同一决策时点约 +168 小时的来源价格；执行则以实际收货、交易保护和最早可卖状态确定退出时点，等待成交与结算单独记录。

建议初版每小时记录前向观察、每日固定时刻推断、准备买入前刷新可匹配报价。当天决策可用已完成的昨日序列和当前已取得的快照；不能使用当天结束才知道的收盘、高低价或之后补齐的历史值。该方案目前是设计，不启动新观察、训练或下单。

初版长期模型可先按统一日粒度构造序列，近期小时信息另外保存；具体取样时点、输入窗口与聚合方法在 P04 冻结。不能把半年每天两点插值成真实小时历史，或把现在才拿到的历史记录假定成过去决策时已发布。不同频率分别记录覆盖和缺失，训练与推断保持相同可得时间定义。

历史成交价格有望改善价格预测目标，但解锁后可供货的求购价格、匹配数量与成本仍需前向证据。当前仅 L0 来源观察，正式数据集、模型和执行准入尚未完成。关联：[主计划](../research/PLAN.md)、[字段契约](UU_FIELD_CONTRACT.md)、[当前状态](../governance/STATE.md)。
