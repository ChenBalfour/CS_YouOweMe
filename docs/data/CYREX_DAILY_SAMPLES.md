# 次时代崭新：日级研究样本与七日目标

版本 **cyrex-daily-samples-guide-1.0**；2026-10-19（北京时间）。构建组件 **cyrex-daily-samples-1.0**，规则配置 **cyrex-daily-spec-1.0**。

本工具将已保存的 SteamDT 显式悠悠小时来源数据，整理为单品的每日研究样本与 28 日序列。它只在本地离线运行，不发市场请求、不训练模型、不产生买卖建议。产物仍是待验收候选样本，`training_approved=false`。

## 用 VS Code 运行

1. 在 VS Code 打开项目 `F:\Codex\CS_YouOweMe`，打开 [cyrex_daily_samples.ipynb](../../scripts/notebooks/cyrex_daily_samples.ipynb)，选择 Python 3.11+ 内核。
2. 运行配置和规则单元格。工作区保持 `research_20261016_v1`；不需要登录信息，也不用写 SQL。
3. 需要生成新版本时，将构建单元格的 `RUN_BUILD=False` 改为 `True`，单独运行该单元格。`OUTPUT_ID=None` 会生成新的输出编号；已有输出目录不会被覆盖。
4. 运行摘要与预览单元格，查看报告、样本和序列。只查看已有结果时跳过构建即可。

Notebook 交付版没有执行输出；默认“运行全部”不会构建或改写研究文件。Notebook 结果显示在单元格，完整文件另存于磁盘。首次使用尚无输出时，摘要会显示 `no_build`。

也可在项目终端执行：

```powershell
python -B scripts/build_research_samples.py build --workspace research_20261016_v1
python -B scripts/build_research_samples.py status
```

先用已有 [SteamDT Notebook](../../scripts/notebooks/steamdt_research.ipynb) 完成每日有限更新，再运行本工具生成一版新样本。两个入口职责分开；样本构建不会自动启动采集。

## 一个样本代表什么

每天北京时间 **10:00** 作为一个决策时点 `t`。输入只取该时点以前已经结束的小时：

- 输入窗口：`[t−28天, t)`，共 **672 小时**。
- 序列：将输入窗口分成 28 个连续 24 小时段，每样本在 `sequence.csv` 中有 28 行。它们按决策时刻对齐，不是自然日午夜分桶。
- 七日参考时点：`t+168小时`，使用在该时点结束的最后一个完整小时的来源收盘。
- 未来路径：`[t, t+168小时)` 的 168 个小时，用于计算未来最低来源 low 相对决策参考收盘的变化。

例：10 月 1 日 10:00 的输入止于当天 09:00—10:00 这个小时；参考目标为 10 月 8 日 09:00—10:00 这个小时的收盘。它不使用 10 月 1 日 10:00 之后的数据生成输入特征。

末个已结束小时的来源收盘仅是研究参考价。它不是你买入时可成交的在售价，七日后的来源收盘也不是可保证成交的求购价。

## 字段与缺失处理

| 输出 | 内容 |
| --- | --- |
| `source_hourly.csv` | 冻结后的单品小时 OHLC、可空来源量额、来源时间和请求追溯 |
| `samples.csv` | 每日决策样本、参考价、输入特征、七日标签、完整性与时间分组 |
| `sequence.csv` | 每样本 28 行的 24 小时 OHLC、来源量额及覆盖标记 |
| `quality_report.json` | 覆盖、缺失、标签成熟状态、隔离与可用样本计数 |
| `report.md` | 人可读摘要、限制和核验结果 |
| `manifest.json` | 组件版本、输入来源上限、规则、源码和产物哈希 |

`samples.csv` 的主要字段如下；其余列以表头为准。价格、收益与量额分列，缺失不补零。

| 字段 | 含义 |
| --- | --- |
| `sample_id` | 固定规格与决策时刻构成的样本编号 |
| `decision_time` / `decision_at_beijing` | 决策时刻，Unix 秒 / 带时区北京时间 |
| `target_time` / `target_at_beijing` | 七日参考时刻，Unix 秒 / 带时区北京时间 |
| `feature_observed_hours` / `feature_expected_hours` | 过去窗口实有小时数 / 应有 672 小时 |
| `feature_complete` | 过去窗口是否完整 |
| `split` / `purged` | 固定 train、validation、test 分组 / 是否标签跨界隔离 |
| `label_status` / `label_ready` | 标签状态 / 是否完整成熟 |
| `x_reference_close` | 末个过去小时的来源参考收盘；过去窗口不完整时也留空 |
| `y_source_close_7d` / `y_source_return_7d` | 七日来源收盘 / 相对参考收盘收益 |
| `y_min_source_low_return_7d` | 未来路径最低 low 相对参考收盘变化 |
| `eligible` | 输入完整、标签完整成熟且未跨界隔离 |

`sequence.csv` 每个 24 小时段必须小时齐全才生成该段 OHLC。来源量/额还要求对应 24 小时全部非空才求和；任一小时缺失或该指标为空，则聚合值留空。来源量额仅作为备查字段，本版不将它们纳入预测特征。

`samples.csv` 的初版价格特征包括：

| 特征组 | 计算口径 |
| --- | --- |
| 1 / 3 / 7 / 14 日收益 | 决策参考收盘与对应滞后来源收盘之比减 1 |
| 7 / 14 / 28 日均线比 | 决策参考收盘与对应 N 个 24 小时段末收盘均值之比减 1 |
| 7 / 14 日波动 | 对应 N 个日段 log-return 的人口标准差，未年化 |
| 7 日高低比 | 对应窗口最高 high 与最低 low 之比减 1 |

完整 28 日窗口缺一小时即 `feature_complete=false`，该行全部 `x_` 特征留空。它仍保留在样本表中供审计，不插值、不补零、不人为制造波动。

标签为七日来源收盘、其相对参考收盘收益，以及未来路径最低 low 相对参考收盘变化。未来 168 小时缺一则为 `future_gap`；源数据还未达到目标时刻则为 `pending_future`，均保留且标签留空，不能提前填标签或当成下跌样本。未来完整但决策参考收盘缺失时标为 `reference_gap`，标签同样留空；其余情况为 `ready`。过去窗口其他位置有缺口时，可以保留成熟标签用于审计，但特征仍留空且 `eligible=false`。未来路径最低 low 是相对起始参考价的风险指标，不是峰谷最大回撤。

## 固定时间划分与隔离

| 分组 | 决策时点（北京时间） |
| --- | --- |
| train | 早于 2026-04-01 10:00 |
| validation | 从 2026-04-01 10:00 起，早于 2026-07-01 10:00 |
| test | 从 2026-07-01 10:00 起 |

训练样本的标签目标时点达到验证起点，或验证样本的标签目标时点达到测试起点时，标记为 `purged`；这些跨界标签不进入可用样本。还必须输入完整、标签完整且已成熟，才计入对应分组的 `eligible` 数量。`eligible` 只表示本版规则下的结构可用，不是正式训练批准。

本工具不随机打散、不根据结果调整边界、不拟合标准化器或模型。后续训练仅可使用训练组拟合参数；测试组保留到固定方案的最终评估。每天的七日标签相互重叠，样本数量不能当作独立交易次数。

## 输出与成本边界

产物位置：

```text
data/local/staging/research_samples/
  <output_id>/
    manifest.json
    report.md
    source_hourly.csv
    samples.csv
    sequence.csv
    quality_report.json
    source/                       本次构建脚本、规则、来源报告快照
  latest_cyrex.json               指向具体输出版本
```

旧输出不覆盖，重新构建产生新版本；`latest_cyrex.json` 只是便利指针。私有样本与原始来源留在本地，不提交 Git。

这版不硬估历史手续费、买卖价差、盘口深度或成交等待，也不把截图所示 232 / 228 元套用于全部历史。由于缺少历史可执行报价、费用与真实解锁记录，来源收益不能换成实际净收益；实际 CD 解锁、出售和结算仍是后续执行评估内容。

本轮验收看输入窗口、标签成熟、缺口保留、分组隔离、版本追溯是否正确；不以预测准确率或收益率宣称完成。相关成果和剩余卡点统一记录在 [当前进展](../PROGRESS.md)。
