## 1. 研究定位与最终产物

研究在实际交易保护、成交等待、资金回款与成本约束下，UU 枪皮的哪些信息能够支持可执行的购买判断。SteamDT 可以作为 UU 数据的采集来源：已明确标注并有平台映射证据的 UU 行情归入相应 UU 观察口径；全平台行情与未映射成交仍仅作辅助。BUFF、Steam 等来源不替代 UU 的成交与执行口径。

最终原型允许输入商品名称、磨损档、版本，以及可选预算和持有周期，输出：

- 对应的精确规格、数据时间和来源；
- UU 价格、可成交性和流动性观察；
- 预期价格变化、净收益概率与风险的不确定性；
- “候选购买／观察／暂不购买／数据不足”的判断及理由；
- 支持判断的数据集、特征、模型和成本版本。

先研究和模拟，再考虑真实资金。自动挂单、改价、发货与真实资金交易属于更远期任务，不是完成本计划的必要条件，不因原型给出信号而自动执行。

研究成功以结论可信、过程可复现和限制清楚为标准。稳定正收益是待检验命题；没有发现有效信号也是有效研究结果。

## 2. 范围与保留的战略原则

| 内容 | 当前处理 |
| --- | --- |
| UU 单平台执行、多平台信息 | 采纳；标签、成本、成交和回款始终归属 UU |
| 先验证、扣成本、看流动性 | 采纳；先建立数据与执行证据，再扩大规模 |
| 有限主力规格 | 采纳；数量由候选质量和采集预算决定 |
| 年化 30%、容量 50 万等目标 | 不预设；收益与容量由数据估计并报告不确定性 |
| 直接指定复杂模型和大技术栈 | 后置；先简单基准，再证明复杂方法的新增价值 |
| 七天内触发即可止损 | 修正；任何退出都必须满足实际可卖和成交条件 |
| 每轮统一扣提现费 | 修正；提现按真实资金退出事件记账 |
| 数据完整率统一要求 95% | 修正；分开定义各字段、时间覆盖和来源可核验程度 |
| 立即开源、边做边发布 | 暂停；先跑通有限闭环，P06 再审核发布清单 |

“千百战”指价格层，不代表战痕磨损。初期普通版与不同磨损分开；StatTrak、纪念品和特殊相位不混入普通规格。P02 按百元/千元字面价格层在本轮采用人民币 `[100,10000)`，逐项核验当前 UU 报价；5000 元以上优先作预算敏感候补。本轮操作边界及修订见 SELECTION_PLAN，不是用户确认的永久范围，不沿用旧价格、权重或容量结论。

刀与手套不进入本轮研究样本。热门与低供给只是筛选线索；低存世量不直接等于可炒作空间，低单价也不直接等于低风险。正式选择同时考虑成交需求、退出能力、属性可比性与数据覆盖。

## 3. 执行机制先于标签

### 3.1 明确不同时间

对每件物品分别记录：决策时间、购买成交时间、物品收到时间、最早可卖时间、出售成交时间、结算时间、资金可复用时间和提现时间。不能用一个“T+7”代替整个过程。

Steam 官方说明，交易收到的 CS2 物品在七天交易保护期间不能转移，且存在交易撤销机制。因此买入第三天触发止损时，不能假设第三天卖出；锁定期间仍需计算持仓价格变化与风险。[官方交易保护说明](https://help.steampowered.com/en/faqs/view/365F-4BEE-2AE2-7BDD)

UU 是否还有额外结算或资金使用等待、撤销后的订单和现金处理、挂单及取消规则，需在 P03 核验。不能未经证据假定“买入七天后立即出售、出售后资金立即可复用”，也不据此推导一年固定 52 次周转。

### 3.2 成本与资金账本

UU 公开费率页列出交易费 0%、提现费 1%，最低 2 元且按元向上取整；页面仍使用 CS:GO 名称。将其作为 2026-10-12 的公开规则参考，P03 再核验实际业务与当前账户适用规则。[官方费率页](https://h5.youpin898.com/pc/chargeStandard.html)

区分购买／出售价格、买卖价差、滑点、成交等待、交易服务费、资金结算、实际提现和待出售库存。余额在平台内复用时，不机械地对每轮交易扣一次提现费。价差已体现在买卖成交价中时，不再重复扣同一项成本。机会成本作为单独情景，不伪造成真实现金手续费。

对已完成的单件往返，可用：

`净收益率 = (出售净入账 - 购买总支出 - 尚未计入的相关费用) / 购买总支出`

平台内表现和实际提现后的现金表现分别报告。未售出或未结算仓位不能当作已变现盈利；超过评估窗口仍未退出的样本需要保留，按库存估值、超时或删失口径报告，不通过删除失败退出样本改善收益。

### 3.3 最小执行假设

先模拟小规模、明确规格的限价购买与出售。挂单不等于成交，市场最低挂牌价不保证我们能买到，最近成交价不保证我们能卖出。不存在必要执行证据时，结果只能标记为估计。

每件枪皮的 float、模板、贴纸及相位可能影响价格。盘口、求购与成交必须在可比属性范围内解释，不能把异质物品当作股票式统一标准合约。自动交易接口与权限尚未验证。

## 4. 模型方向与研究问题

主方向为 **UU 可执行净收益与退出能力的联合研究**。辅助平台用于检验是否存在新增信息，不预设其具有领先优势。

| 研究问题 | 需要检验的假设 | 必要信息 |
| --- | --- | --- |
| 多平台信息传导 | 外部变化能否改善 UU 的样本外预测 | 同规格、币种、时效与当时可得的信息 |
| 热度、供给与价格 | 关注及供给变化能否提供稳定信息 | 连续快照；来源统计范围明确 |
| 流动性与退出 | 信号出现后能否在预算和时间内完成交易 | UU 可比在售、求购、成交与订单状态 |
| 属性溢价 | 同档内 float、模板、贴纸是否影响成交 | 逐件属性及属性缺失标记 |
| 事件与状态变化 | 规则变化是否改变上述关系 | 事件证据、固定窗口、分组及干扰因素 |
| 购买决策 | 扣成本后是否优于简单基准及暂不交易 | 执行约束、持仓账本、样本外验证 |

2025 年 10 月市场事件可作为背景研究，但具体事件定义、时间和影响范围需要核验，不将“黑蛋”相关行情与 Valve 规则更新自动视为同一事件。事件研究与可执行预测分别报告，不能从单个事件的前后变化直接推导稳定交易能力。

### 4.1 数据与标签能力分级

| 级别 | 数据支持 | 允许的结论 |
| --- | --- | --- |
| L0：观察标签 | 展示价格或来源行情 | 价格变化研究，不宣称能按该价成交 |
| L1：模拟执行标签 | UU 可比报价、时间与成交信息，加明确执行假设 | 估计净收益、成交能力及假设敏感性 |
| L2：实际执行标签 | 实际订单、成交、结算和现金账本 | 该规模与该规则下已观察的执行表现 |

先确认达到哪一级，再决定标签。未知平台代码、总览行情和辅助平台成交不能直接标作 UU 执行数据。

初步采用跨越实际最早可卖时间的持有窗口，14／21 日可作为待验证候选；具体窗口在 P04 冻结，不因回测好看不断改动。收益预测、正净收益概率和可退出概率分开定义，再组合决策。数据缺失的未知结果不标成零收益。

横截面排名允许研究，但“未来收益前 20%”不能自动成为购买标签；全板块下跌时前列也可能亏损。保留绝对净收益门槛、成交能力约束和暂不购买选项。

Triple Barrier 仅在屏障与可执行时间一致时考虑；锁定期间的价格触碰可作风险观察，不能作为已经完成的退出。Meta-Labeling 后置，不提前声称第二层模型能决定最优仓位。

### 4.2 特征路线

按实际可得数据逐组增加，不预设 30、50 或 80 个特征：

1. UU 价量与波动：滞后收益、波动、成交稀疏程度、报价时效。
2. UU 可成交性：可比价差、在售与求购结构、报价变化、退出等待。
3. 辅助平台：经过币种、钱包／现金计价和更新时间处理的相对变化。
4. 供给与热度：可核验的连续观察；当前存世量不能回填成过去的供给。
5. 属性与事件：float、模板、贴纸、来源事件和市场状态。

每项特征记录定义、单位、窗口、信息可得时间、缺失处理和版本。采用决策时点已可见的信息，不用“统一滞后一天”替代可得性审查。模拟执行收益中再考虑单件差异，不把规格均价当作所有个体的价格。

### 4.3 算法路线

先验证不交易、简单动量／流动性规则和普通统计基准，再研究正则化回归、逻辑回归；聚类用于描述结构，不直接证明预测收益。若非线性特征能带来可重复的新增效果，再比较 LightGBM。

LambdaRank 属于可选排序研究，需要同一决策时点的横截面分组、明确的相关性标签与排序评估。官方文档规定排序标签使用整数相关性等级，不能未经转换直接当成任意连续收益。[LightGBM 参数说明](https://lightgbm.readthedocs.io/en/latest/Parameters.html)

论文复现优先选择与可得数据、交易保护和执行条件匹配的方法。每篇记录原论文、公式、数据差异、参数及复现偏离。集成、HMM、深度学习不作为必选清单；方法复杂度由基准差距和有效样本量决定。

## 5. 数据设计与验收边界

### 5.1 来源分工

| 优先级 | 来源 | 作用 |
| --- | --- | --- |
| 核心 | UU 数据，可由 UU 或 SteamDT 的明确 UU 来源取得 | 商品身份、可比在售／求购、成交、时间和执行规则；逐字段确认归属 |
| 来源兼辅助 | SteamDT | 明确 UU 行情的采集来源，以及目录映射、其他平台报价、来源历史与供给观察 |
| 按假设补充 | BUFF、Steam 等 | 检验新增信息；不要求先采齐所有平台 |
| 按研究补充 | 官方规则、更新与公开事件 | 规则版本与事件证据 |

现有 SteamDT 的 `ALL` 行情及未映射平台代码，只能按原来源口径使用。P03 应建立映射证据，不根据价格相近或代码序号猜测 UU 身份。

plan-1.3 核验补充：网页仅将逐笔代码 1 显示为 Steam、0/2/3 显示为三方平台，并说明三方记录为推算。market-comparsion 明确 UU 行的价格/数量可作来源汇总，但缺乏可比属性、价位深度和两侧独立时间；交叉报价保留并标异常，不形成执行标签。UU 直接入口 429 后停止，当前结算规则仍待核验。具体边界见 [字段契约](../data/UU_FIELD_CONTRACT.md)与[有限报告](P03_VERIFICATION_REPORT.md)。

颗粒度以来源真实提供的事件时间和逐件属性为上限。保留逐笔及快照，再显式聚合；不能由日线插值出“真实小时／逐笔”，也不为追求更细而重复采集同一状态。

### 5.2 时间范围与两类数据集

北京时间 **2025-06-01** 保留为历史研究目标起点，其可得性按 UU 和每个辅助来源分别核验。

- 历史研究集：经核验的来源历史，供价格与事件研究；不能假称拥有当时的 UU 盘口或完整供给。
- UU 前向观察集：规则确认后持续采集当时可见的 UU 信息，供后续预测与执行模拟。

拿不到 UU 历史盘口时，记录缺口并建立前向观察；不以其他平台盘口、当前存世量或合成值替代。两类数据集分别有 ID、用途和能力等级。

### 5.3 字段要求

P03 形成字段契约，P04 构造数据集。候选字段包括：

- 来源与身份：venue、source、来源商品编号、英文规格、版本、磨损、相位；
- 属性：精确 float、模板、贴纸、必要的物品／挂牌标识；
- 时间：事件时间、来源更新／可得时间、采集时间、可卖与结算时间；
- 市场：价格、币种、可比数量、在售／求购／成交状态及原始口径；
- 追溯：请求 ID、原始响应 SHA-256、解析和 schema 版本；
- 质量：缺失、过期、重复、异常、平台未确认、可得时间不明。

这些是需求，不是已取得字段。账号、认证信息及与研究无关的用户资料不进入训练特征或发布包。

### 5.4 质量验收

| 项目 | 分母 / 判断依据 |
| --- | --- |
| 请求成功率 | 已计划且实际尝试的请求 |
| 时间覆盖 | 约定采样时间槽；停机、缺失与来源无变化分别记录 |
| 属性完整率 | 应具有该属性的有效记录 |
| 报价时效 | 来源更新时间与决策时点之差 |
| 来源成交覆盖 | 可取得的来源分页及总数证据；无总数时不宣称真实全市场完整率 |
| UU 身份 | 每条执行记录的平台与编号映射证据 |
| 标签可用率 | 满足时间、执行和结果可观察条件的样本 |
| 可复现性 | 冻结输入、代码、配置与变换后可重复生成 |

在采样方式确定后，P03 定义可测指标，P04 冻结阈值和降级规则。核心来源未知、时间语义不明或执行标签不成立时，不能进入交易有效性训练。

## 6. 验证、回测与决策门

按时间前推验证，不随机打散整个时间序列。训练窗口内拟合预处理；去除与验证窗口重叠的训练标签，并按标签持有跨度及信息延迟设置必要的间隔。Purging、Embargo 服务于具体泄漏风险，不作为固定术语清单。

保留最终未参与调参的时间段。按日期整体切分横截面，考虑同涂装多个磨损的关联。当前热度筛出的历史商品属于回顾性样本，需报告选择与幸存者偏差；前向名单每次版本化。

主要检查：

- 相对不交易、同板块基准和简单规则的样本外表现；
- 收益误差、排序能力、概率校准与时间段稳定性；
- 成交／退出概率、等待时间、库存风险与实际可复用资金；
- 成本、延迟、报价过期及缺失处理下的敏感性；
- 回撤、尾部风险、样本规模与不确定性；
- 辅助平台、供给和属性特征的分组消融，确认新增信息来源；
- 实验数量与调参记录，避免从大量尝试中挑选幸运结果。

不把 Rank IC 单点大于 0.03 或年化大于 30%设为自动成功条件。容量根据已核验成交与冲击估计，不先承诺十万、五十万或百万资金规模。仓位和退出参数作为待评估配置；模型不能保证随时止损。

表中后续内容是计划，不是本轮执行授权。每次对话只完成用户指定的部分；完成后报告交付物和限制，停止。下一次明确指示即确定新的工作范围，无需重复索取同一授权。

| Part | 范围与交付物 | 验收条件 | 本轮状态 |
| --- | --- | --- | --- |
| P01 | 本计划、文件管理、资产登记、阶段状态与执行约束 | UU 目标、成本／时间／标签、顺序、旧资产与发布规则一致 | 本轮完成 |
| P02 | 热门候选调查、有限主力名单、入选／候补理由与版本 | 有限调查后形成有条件验证名单；需求与退出不足的证据明确列 unknown，不沿用旧权重 | 初选交付完成，交易适配待 P03 确认 |
| P03 | UU 来源和执行规则核验、字段契约、对应爬虫、有限试跑、失败恢复与存储预算 | 核心字段及来源成立；试跑能追溯和恢复；明确缺失与历史不可得范围 | 两规格有限交付完成；L0 通过，L1/L2 与完整执行验收未通过 |
| P04 | 正式采集与数据集、版本清单、质量报告、标签与划分协议 | 输入冻结、可复现；仅接纳审查合格记录；训练／验证／测试协议事先固定 | 未开始 |
| P05 | 因子、简单基准、论文复现或适配模型、成本回测、模拟决策原型与研究报告 | 有限端到端闭环跑通；信号有效或无效均按证据报告；结果可追溯 | 未开始 |
| P06 | 旧仓库资产复审、发布允许清单、可复现说明、源码与适当示例 | 密钥／个人信息检查通过；只发布已审查资产；按用户当时指示处理已有公开内容 | 未开始 |

P02 可做支持选品的有限市场调查，不能据此启动长期全量采集。P03 只用有边界的试跑验证爬虫，不把试跑产物自动升级为正式数据集。P04 才进行正式数据集构建；P05 才训练和评估。

某部分证据不足时，在该部分记录问题、补充验证或调整方向，不靠进入下一部分掩盖缺口。不设置六个月之类的硬排期，工作量由来源可得性与验收结果决定。
