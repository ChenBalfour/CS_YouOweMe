# 武器皮肤的因子与课程建模方案

状态：研究设计，尚未训练模型或得到样本外表现。课程要求包含回归、分类或聚类；本项目建议以回归为主、分类作对照、聚类作探索。

## 1. 问题与当前限制

目标是研究：在某一天已知的价格、波动、供给和报价信息，能否预测同一商品规格未来的价格变化。这里“量化因子”指可计算的预测特征，不要求先做统计学中的潜在因子分析或 PCA。

当前只有 20 个主动访问的商品、180 条跨平台报价、267 条字段有限的关联规格，全部属于一次快照。9 个平台的报价不是 9 个独立商品，关联规格也不是 267 条完整历史样本。现在可以做缺失率、陈旧报价、价格分布、跨平台对比，不能验证未来收益预测。

价格是挂牌报价，不是实际成交价。公开页的“今日推算成交”是估算，涨跌幅原值的量纲与计算窗口尚需核实。[SteamDT K 线接口](https://doc.steamdt.com/428124801e0)明确不包含成交数据；返回数组列定义、币种和周期仍需实测确认。不能编造历史成交量、历史持有人数或历史存世量。

## 2. 研究对象与目标变量

先固定普通版武器皮肤、磨损档位、一个经验证的数据平台和报价口径。建立日频面板，一行的键为 `(日期, market_hash_name, 主平台)`。版本和磨损由精确市场名区分；这里不包含单件饰品 float、图案编号或贴纸溢价。

在每天固定北京时间截面 t，只使用截至 t 已能获得的记录。平台来源时间必须有效、不晚于 t，且满足预先固定的数据年龄阈值。禁止把今天首次观察的供给字段回填到过去。平台间特征另行聚合，不能把每个平台报价展开成重复的独立标签。

第一阶段建议预测未来 14 个自然日的**同平台挂牌价格收益率**：

```text
y_price(i,t) = P(i,t+14) / P(i,t) - 1
y_up(i,t) = 1 if y_price(i,t) > 0 else 0
```

这是研究代理目标。未来日期没有有效报价时，标签留空并说明原因；不能使用后来的价格回填。14 日是待验证的研究窗口，可在验证集比较 14 / 30 日，再固定方案，不能反复看测试集选择最好的窗口。

交易收益标签要等可执行报价、费用和交易状态明确后另建：

```text
entry_cost = executable_buy_price * (1 + buy_fee) + entry_fixed_cost
exit_cash  = executable_sell_price * (1 - sell_fee) - exit_fixed_cost
y_net      = exit_cash / entry_cost - 1
```

费用按平台、交易路线和当时规则记录，不设一个通用费率。卖出挂牌价不等于能成交的退出价格；求购价也需核对数量、时间和适用规格。不能把报价收益模型的输出直接命名为“购买成功概率”。

Steam 的 [交易保护说明](https://help.steampowered.com/en/faqs/view/365F-4BEE-2AE2-7BDD)规定 CS2 经交易收到的物品有 7 日保护期，其间不能转移。建模和回测需结合实际获取路线、物品可交易/可上架时间及平台资金结算规则；采用 14 日窗口不意味着所有交易都一定可执行。

## 3. 从简单、可解释的候选因子开始

下表是研究假设，方向和效果需要验证，不预设它们赚钱。先选少量、不高度重复的特征。

| 因子 | 示例计算 | 数据要求与限制 |
| --- | --- | --- |
| 7 / 30 日动量 | `P_t / P_(t-k) - 1` | 同平台、同口径历史价格；不能把未核实的页面涨跌幅直接代入 |
| 偏离均价 | `P_t / mean(P_(t-6:t)) - 1` | 探索短期回归或趋势，方向由训练数据检验 |
| 30 日波动 | 过去 30 个日收益率的标准差 | 正数有效价格；缺失窗口不足时留空 |
| 30 日回撤 | `P_t / max(P_(t-29:t)) - 1` | 衡量近期价格下行状态 |
| 供给变化 | `log(S_t) - log(S_(t-7))` | 需要连续采集且正数的存世量 S；口径变化单独标记 |
| 平台报价离散度 | `(max(ask)-min(ask))/median(ask)` | 仅纳入币种、时间、版本一致的有效平台；现金与钱包价格分开处理 |
| 买卖价差 | `(ask-bid)/((ask+bid)/2)` | 需要有效同平台求购价；公开页没有该字段，暂不可用 |
| 流动性代理 | 在售数量、求购数量、经核实的成交统计 | 当前数量不能倒推历史；成交估算只能标为代理，不能称真实成交量 |

每个因子记录计算公式、窗口、可用时间、单位、缺失条件和数据来源。必要时用训练集拟合的截尾与标准化处理极端值；不要用全样本分位点处理历史数据。武器类别、磨损、价格区间可作为控制变量，避免把高价饰品与低价饰品的结构差异误判成因子作用。

先做单因子检查：每个日期计算因子与未来收益的 Spearman 相关（Rank IC），看均值、日期稳定性和样本数量；再比较按因子分组的未来收益。[Alphalens 的因子评估接口](https://quantopian.github.io/alphalens/alphalens.html#alphalens.performance.factor_information_coefficient)可作方法参考。本项目不以旧工具安装作为前提。组数取决于每日有效商品数量；只有 20 个商品时，分成许多组会非常不稳定。

## 4. 课程算法怎样落地

| 任务 | 第一版算法 | 输入 / 输出 | 用途与评估 |
| --- | --- | --- | --- |
| 回归，主模型 | [Ridge 回归](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html) | 因子 X → 未来 14 日报价收益 `y_price` | MAE、样本外 R²、每日 Rank IC；与预测 0 收益和简单动量基准比较 |
| 分类，对照模型 | [逻辑回归](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html) | 同一 X → 报价上涨概率 `y_up` | ROC-AUC、PR-AUC、Brier 分数、混淆矩阵；检查类别比例和概率校准 |
| 聚类，探索分析 | [KMeans](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.KMeans.html) | 波动、价格、可用流动性特征 → 分组 | 轮廓系数、群组特征和稳定性；分组不是购买标签 |

Ridge 的 L2 正则化适合作为相关因子下的可解释基线。先回答简单模型是否优于基准，再考虑随机森林、梯度提升等非线性模型。聚类的缩放参数和中心只用训练期拟合，验证/测试期分配到已有中心，不在全样本上先聚类再回测。

课程交付可包含三种算法，但不必把三种算法强行串成一个交易系统。回归和分类使用同一日期划分，便于公平对照；聚类帮助描述市场，不作为证明预测能力的指标。

## 5. 验证必须按时间走

禁止随机打散商品×日期行。相邻日期共享市场冲击，未来 14 日标签还会重叠。以完整日期块进行滚动或扩展窗口验证：训练期 → 隔离期 → 验证期；调参完成后，在保留的较晚测试期做一次报告。

进入验证起点之前，所有训练标签的结束日期必须严格早于该起点；14 日标签需要相应自然日隔离。验证与最终测试之间也按标签可用时间隔离。可参考 scikit-learn [TimeSeriesSplit 的 gap 参数](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)，但面板数据必须按日期分组，不能直接按堆叠后的行数设置 gap。

缺失值填补、特征选择、截尾、标准化和模型调参均只在训练期拟合，再应用到后续日期。同商品留在后续日期符合本项目预测对象；另外留出未见商品可以检查泛化，但不能替代时间验证。特征窗口不足、数据过期和交易资格不符的记录应按事先规则排除，记录每日覆盖率。

报告样本外误差、IC 的日期分布、各时间段结果和基准差异。14 日重叠收益存在相关性，不能把每一行当独立样本推断显著性；有足够日期后可采用日期块 bootstrap。不要从大量因子和参数里挑出一次最高回报，省略失败实验。

## 6. 回测与未来购买决策

先做只买入的排名组合模拟，例如有效商品中预测最高的一组，与同商品池等权持有基准比较。固定再平衡日期、持有期、预算和单商品上限；检查持仓锁定、资金可用、成交容量、滑点及买卖费用。因子分组里的高低组差异可以用于分析，但不能假定现实中可以卖空饰品。

仅有挂牌历史时，结果应叫“报价组合模拟”，必须说明成交假设，不能声称真实可执行收益。报告费用敏感性、换手、最大回撤、未成交与缺失数据处理，避免只有累计收益曲线。

未来系统的顺序应是：

```text
输入武器 / 涂装 / 磨损 / 版本
→ 匹配精确商品规格
→ 检查数据新鲜度、交易资格和预算
→ 计算当时可得因子
→ 给出预测、置信信息和费用情景
→ 输出候选 / 观察 / 跳过 / 数据不足，以及理由
```

预测上涨也可能不足以覆盖成本。“购买候选”需要事先定义、经样本外检验的阈值；数据不足时允许不作判断。系统先做研究与决策辅助，交易执行是另一阶段。

## 7. 下一批数据与阶段验收

建议的起步设计是扩展到 100–300 个固定武器皮肤规格，争取 180–365 天同平台日频价格；这是研究采样计划，不是保证统计有效的最小样本量。须包括可追溯的日期范围、缺失和退市/不可售记录，避免只保留今天仍热门的幸存商品。供给和报价数量等字段从实际开始采集的日期积累，不能假设价格历史接口同时提供它们。

| 阶段 | 可交付结果 | 进入下一步的条件 |
| --- | --- | --- |
| 接口核实 | 少量真实 K 线响应、字段/周期/币种说明、测试样本 | 数据来源和语义可验证 |
| 日频数据集 | 固定商品池、时间对齐后的面板、覆盖率报告 | 有足够历史计算因子及未来标签 |
| 单因子研究 | 因子字典、IC、分组收益和失效时间段 | 指标按日期计算、无未来信息 |
| 课程建模 | Ridge、逻辑回归和聚类的可复现实验 | 时间验证、训练期预处理、基准比较 |
| 决策原型 | 费用与交易限制下的报价模拟、可解释输出 | 清楚披露成交假设与样本外表现 |

当前版本完成目录整理和这份方案，没有训练模型、回测收益或实际购买推荐。下一项实际工作是验证官方历史接口与数据覆盖。
